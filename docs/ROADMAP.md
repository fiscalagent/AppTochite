# AppTochite — Roadmap

> Документ отражает историю разработки, текущее состояние и планы.
> Текущая версия приложения: **v1.54.0** · Обновлено: май 2026

---

## Общая цель продукта

Мобильное PWA-приложение для профессиональных заточников ножей. Два сценария:
- **Малый бизнес** — клиенты, статусы заказов, выручка
- **Личный журнал** — нулевой клиент «Я», фиксация своих заточек

Платформа: Android (90%). Работает офлайн, без сервера, данные хранятся локально (IndexedDB).

### Фаза 1 — MVP
**Статус: ✅ Завершено**

**Клиенты**
- C-1 Список клиентов
- C-2 Карточка клиента
- C-3 Форма добавления / редактирования клиента

**Инфраструктура**

### Фаза 17 — Голосовой ввод *(v1.47–v1.54)*
**Статус: ✅ Завершено**

- `useVoiceInput` хук: Web Speech API, `isAvailable / isListening / start / stop`
- `useTwoPhaseVoice` хук: двухфазный ввод — распознаём → список совпадений → довыбор голосом или тапом
- `MicButton` компонент: три состояния (доступна / слушает-анимация / недоступна-disabled)
- Feature flag: `src/config/features.ts`; opt-in через настройки в «О программе»
- Fuzzy match: `voiceMatch.ts` — транслитерация + bigram-сходство + щадящий матчинг для русского произношения
- Голос выбирает нож, сталь, камень (двухфазно), клиента, HRC; автодовыбор: после списка микрофон сам слушает уточнение 1000 мс
- В офлайне кнопка `disabled`, тап → toast «Голосовой ввод недоступен офлайн»

### Фаза 18 — Диктовочный режим *(итерация 2, ожидает релиз)*
**Статус: ✅ Код реализован, ждёт боевой проверки**

- `parseCommand` (`utils/voiceCommand.ts`) — strict-грамматика команд с префиксом поля, 67 юнит-тестов
- `useDictationMode` (`hooks/useDictationMode.ts`) — непрерывное распознавание с авто-перезапуском и счётчиком ошибок (3 подряд → автостоп)
- `DictationButton` / `DictationIndicator` / `DictationCandidates` — UI диктовки в шапке Z-1
- Полная цепочка команд: поля Приёмки (`клиент / нож / сталь / требуется / примечание`), поля Заточки (`камень + добавить / угол / цена / примечание`), навигация (`дальше / назад / сохранить / готово / стоп / отмена → да`), коррекции (`сотри / удали последний камень / повтори`)
- Подтверждение fuzzy по Варианту 4 (auto-select при высокой уверенности, иначе список кандидатов)
- План и тесты: `docs/voice-input-plan.md`, `docs/TESTING.md` (DI-1…DI-45)

### Трек надёжности данных

Описан подробно в `AppTochite_spec_v0.4.md` (раздел 3.3, «Планируемые улучшения надёжности»). Закрывают классы потери данных, которые **облачный бэкап не закрывает** или закрывает не полностью. Часть пунктов — обязательная инфраструктура для будущего облака.

| Функция | Закрывает | Связь с облаком | Приоритет |
|---|---|---|---|
| Soft delete + корзина | Случайное удаление пользователем — самый частый кейс | Обязательная база для мультидевайс tombstones | **Высокий** |
| Автоснапшот перед миграцией схемы | Ошибки в нашем релизе | Ортогонально | **Высокий** |
| История бэкапов (N последних, а не один) | Битый бэкап перезатёр хороший | Тот же паттерн нужен в облаке | Средний |
| Web Share API для бэкапа | Off-site копия без OAuth | Частичная альтернатива облаку — может закрыть запрос раньше | Средний |
| Проверка целостности после записи | Ложное чувство безопасности при битом бэкапе | Ортогонально | Средний |
| Эскалация напоминания о бэкапе | Активный пользователь смахивает напоминания неделями | Ортогонально | Низкий |
| PWA install prompt про сохранность | R-3: пилоты использовали как вкладку | Ортогонально | Низкий |

## Известные технические долги

- `cleaner.html` — вспомогательная страница вне React-приложения, не должна попадать в production
- Фото хранятся как `base64[]`: сжатие добавлено, но при большом числе заточек с фото IndexedDB всё равно растёт; потенциально нужен File System Access API для хранения файлов (отдельно от бэкапа)
- Тесты (Vitest) покрывают логику БД, утилиты и voiceMatch — UI-компоненты и экраны не покрыты
- 2 теста в `seed.test.ts` падают из-за неожиданного поведения при потере таблицы `meta` — исправить при ближайшем рефакторинге seed-логики
