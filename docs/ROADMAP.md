# AppTochite — Roadmap

> Документ отражает историю разработки, текущее состояние и планы.
> Текущая версия приложения: **v1.14.0** · Обновлено: май 2026

---

## Общая цель продукта

Мобильное PWA-приложение для профессиональных заточников ножей. Два сценария:
- **Малый бизнес** — клиенты, статусы заказов, выручка
- **Личный журнал** — нулевой клиент «Я», фиксация своих заточек

Платформа: Android (90%). Работает офлайн, без сервера, данные хранятся локально (IndexedDB).

### Фаза 0 — Основа проекта
**Статус: ✅ Завершено**

- Инициализация стека: Vite + React 18 + TypeScript + Dexie.js + React Router v6 + PWA

- Design tokens (`tokens.css`) — цвета, отступы, типографика

### Фаза 1 — MVP
**Статус: ✅ Завершено**

**Клиенты**
- C-1 Список клиентов
- C-2 Карточка клиента
- C-3 Форма добавления / редактирования клиента
- Нулевой клиент «Я» (`isSelf: true`) — создаётся при первом запуске, не удаляется

**Заточки**
- Z-1 Форма заточки (stepper: Приёмка → Заточка)
- Z-2 Детальная запись заточки (просмотр)
- Статусы: `accepted` / `done`, автоматическое проставление `doneAt`
- H-1 Лента заточек (история), группировка по месяцам

**Справочники**
- S-1 Камни, S-2 Стали, S-3 Ножи
- Предзаполненные данные: ~28 камней, ~100 сталей, ~200 ножей

**Инфраструктура**
- PWA: офлайн-режим, установка на устройство
- Нижняя навигация с быстрой кнопкой «+ Заточка»

### Фаза 7 — Надёжность и UX *(v1.1–v1.3)*
**Статус: ✅ Завершено**

- Напоминание о бэкапе — модальное окно раз в 7 дней (не ранее 3 дней после первого запуска)

- Лимит: не более 5 фото «до» и 5 фото «после» на заточку
- Выбор источника фото — bottom sheet: камера или галерея (`PhotoSourceSheet`)
- Автотесты Vitest: 58 тестов для бэкапа и операций с БД
- Печатная инструкция для пользователей (`public/guide.html`)

## Статус: готовность к бета-запуску

> Оценка проведена в мае 2026, перед выкаткой на 20–30 пилотов.

### Ядро — реализовано полностью ✅

Весь основной сценарий работает: создать клиента → создать заточку → отметить готовой → сделать бэкап. Справочники, поиск, фото, история — всё на месте.

### Пробелы относительно MVP-спеки

| Функция | Статус | Приоритет |
|---|---|---|
| Суммарная выручка в карточке клиента (C-2) | ❌ Не реализовано | Низкий |
| S-4 — карточка позиции справочника с кнопкой «Использовать» | ❌ Не реализовано | Низкий |
| Drag-to-reorder камней в форме заточки | ❌ Не реализовано | Низкий |

Все три пункта — не блокеры для бета-запуска.

### Риски при выкатке на пилотов

| # | Риск | Уровень |
|---|---|---|
| R-1 | Потеря данных: бэкап ручной, нет автоматического напоминания при выходе | 🔴 Высокий |
| R-2 | Бэкап-файл падает в «Загрузки» на телефоне — легко потерять при смене устройства | 🟡 Средний |
| R-3 | Пилоты могут не установить PWA, использовать как вкладку — разные IndexedDB | 🟡 Средний |
| R-4 | URL `github.io/AppTochite` — не запоминается, нет собственного домена | 🟠 Низкий |
| R-5 | `cleaner.html` доступен по прямому URL — риск случайного сброса данных | 🟠 Низкий |

> **R-1 закрыт частично** через `BackupReminder` (раз в 7 дней). Но компонент срабатывает только при открытии приложения, не при закрытии. При активном использовании пилот может делать 15–20 заточек за 7 дней без бэкапа.

## Известные технические долги

- `cleaner.html` — вспомогательная страница вне React-приложения, не должна попадать в production
- Фото хранятся как `base64[]`: сжатие добавлено, но при большом числе заточек с фото IndexedDB всё равно растёт; потенциально нужен File System Access API
- Тесты (Vitest) покрывают только логику БД и утилиты — UI-компоненты и экраны не покрыты
- Дизайн-система (`AppTochite_design_system_v0.3.md`) содержит токены `--status-inwork`, хотя статус «в работе» удалён из кода — при следующем обновлении убрать
