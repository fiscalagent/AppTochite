## Общая цель продукта

Мобильное PWA-приложение для профессиональных заточников ножей. Два сценария:
- **Малый бизнес** — клиенты, статусы заказов, выручка
- **Личный журнал** — нулевой клиент «Я», фиксация своих заточек

Платформа: Android (90%). Работает офлайн, без сервера, данные хранятся локально (IndexedDB).

Весь основной сценарий работает: создать клиента → создать заточку → отметить готовой → сделать бэкап. Справочники, поиск, фото, история, голос, диктовка, мультиязычность ru/en, три уровня автобэкапа (браузер/папка/облако), корзина, цифровая визитка, игры-тренажёры — всё на месте. Распространяется двумя каналами: PWA (GitHub Pages) и off-store Android APK (Capacitor). Приложение по-прежнему помечено как бета в пользовательской инструкции — раздел «Пробелы» ниже не пуст, а тестовая база пока не крупная.

### Риски

| # | Риск | Уровень | Комментарий |
|---|---|---|---|
| R-2 | Голосовой ввод работает только в Chrome/Android — на iOS недоступен, в APK тоже (Web Speech API нет в WebView) | 🟡 Средний | Без изменений — ограничение платформы |
| R-4 | PWA живёт на `fiscalagent.github.io/AppTochite` — не запоминается | 🟠 Низкий | Смягчено: есть промо-домен `apptochite.github.io` (страница загрузки APK) и кнопка «Поделиться приложением» в самом приложении |
| R-5 | `cleaner.html` доступен по прямому URL — риск случайного сброса данных | 🟠 Низкий | Без изменений, см. «Известные технические долги» |

Закрыто с прошлой оценки: **R-1** (потеря данных из-за невключённого автобэкапа) и **R-3** (пилоты используют PWA как вкладку, разные IndexedDB) — оба закрывает связка `StorageRiskAlert` (детектор вытесняемого хранилища) + автобэкап по умолчанию (OPFS, без явного включения) + `DataLossAlert` (sentinel-детектор уже случившейся потери) + install-нуджи + альтернативный канал off-store APK, где вытесняемого хранилища вовсе нет.

## Известные технические долги

- `cleaner.html` — вспомогательная страница вне React-приложения, не должна попадать в production
- Фото хранятся как `base64[]`: сжатие добавлено, но при большом числе заточек с фото IndexedDB всё равно растёт; см. «Вынос фото заточек в отдельную таблицу» в бэклоге выше
- Тесты (Vitest) покрывают логику БД, утилиты, voiceMatch/voiceCommand, refSync, cloudBackup, merge — но не UI-компоненты и экраны (427 тестов, все зелёные на момент этой сверки)
