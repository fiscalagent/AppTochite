# Голосовой ввод — план реализации

> Статус: ✅ Реализовано (v1.47–v1.54)

---

## Концепция

Голос как дополнение к текстовому вводу (progressive enhancement). Форма работает без голоса в штатном режиме, микрофон только ускоряет заполнение. В офлайне фича недоступна, но ничего не ломается.

**Opt-in:** пользователь явно включает голосовой ввод в разделе «О программе» → «Настройки». По умолчанию выключен.

### Логика статуса

Дефолт — `accepted`. Если в распознанном тексте есть ключевое слово — переключаем в `done`:

```
готово, готов, выполнено, сделано, закончил, завершено
```

Переход однонаправленный (`accepted → done`). При срабатывании — тост «Статус изменён на "Готово"».

## Двухфазный голосовой ввод (`useTwoPhaseVoice`)

Ввод для полей-справочников (нож, сталь, камень, клиент):

1. **Фаза 1 — распознавание:** нажимаем кнопку, произносим значение
2. **Фаза 2 — уточнение:** показывается список совпадений под полем; микрофон автоматически слушает ещё 1000 мс для голосового довыбора (например: «120» выбирает Naniwa 120 FEPA)
3. Выбор тапом или голосом («8» → AUS-8, «третий» → 3-й вариант)

Список совпадений не исчезает сам — только по выбору или закрытию.

## Fuzzy match (`src/utils/voiceMatch.ts`)

- **Транслитерация:** русские буквы → латиница для сравнения с англоязычными названиями (Нанива → Naniwa)
- **Bigram-сходство:** нечёткое совпадение строк, устойчивое к ошибкам произношения
- **Щадящий матчинг:** специальные правила для русского произношения английских брендов (например, «гринderman» → Grinderman)
- **Числовой матч:** «восемь» / «8» → марки стали содержащие «8»
- **Тест:** `src/utils/voiceMatch.test.ts`

# Итерация 2: диктовочный режим (hands-free, Z-1)

> Статус: ✅ Реализовано, ожидает боевой проверки на Android (DI-1…DI-45 в `TESTING.md`)

## Цель

Заточник может полностью заполнить форму заточки (Z-1) **без касаний экрана** — после одного тапа «включить диктовку». Микрофон слушает непрерывно, парсер интерпретирует каждую фразу как команду.

Скоуп: **только `SharpeningForm.tsx`** (создание новой и редактирование существующей). Z-2 (детальный просмотр) в пилот не входит.

## Два режима микрофона на форме

- **Точечный** (итерация 1, уже работает) — mic у конкретного поля, диктовка одного значения. Остаётся для коррекций.
- **Диктовочный** (новый) — большая кнопка-тумблер сверху формы. Включён → SR слушает с авто-перезапуском в `onend`, парсит каждую фразу как команду. Один глобальный индикатор «слушаю» (пульсация) в шапке + последняя распознанная фраза мелким шрифтом.

## Грамматика команд (strict — всегда с префиксом поля)

### Шаг 1 — Приёмка

| Фраза | Действие |
|---|---|
| `клиент <имя>` | Fuzzy по справочнику клиентов |
| `нож <название>` | Fuzzy по knives |
| `сталь <название>` | Fuzzy по steels |
| `требуется заточка` / `правка` / `правка рк` / `ремонт` | Toggle chip в поле «Требуется» |
| `примечание <текст>` | Дописать в textarea (через пробел, если уже что-то есть) |

### Шаг 2 — Заточка

| Фраза | Действие |
|---|---|
| `камень <название>` | Fuzzy по stones; **двухфазно** — ставит в инпут, ждёт `добавить` |
| `добавить` | Добавить выбранный камень из инпута в список |
| `удали последний камень` | Pop последнего из списка |
| `угол <число>` | Подстановка в number input |
| `цена <число>` | Подстановка |
| `примечание <текст>` | Дописать в textarea |

### Навигация и финализация

| Фраза | Действие |
|---|---|
| `дальше` / `следующее` | Шаг 1 → Шаг 2 (со Шаг 2 — игнор + тост) |
| `назад` | Шаг 2 → Шаг 1 (со Шаг 1 — игнор) |
| `сохранить` | Submit с текущим статусом (по умолчанию `accepted`) |
| `готово` | Статус → `done`, `doneAt = now()`, submit, далее **ручной** поток фото-после |
| `стоп` / `пауза` | Выключить диктовочный режим (форма не сохраняется) |
| `отмена` → `да` (5 сек) | Выход из формы без сохранения. Двухфазно из-за деструктивности |

### Коррекции (на любом шаге)

| Фраза | Действие |
|---|---|
| `сотри <поле>` / `очисти <поле>` | Очистить значение поля (`сотри сталь`, `сотри примечание`) |
| `повтори` / `что услышал` | Показать тост с последней распознанной фразой |

### Strict-правило для команд не своего шага

Команда шага 2 (`угол 20`) на шаге Приёмка — **игнорируется** + тост «команда недоступна на этом шаге». Авто-переключения нет.

## Подтверждение fuzzy-выбора (Вариант 4 — гибрид по уверенности)

Для полей с fuzzy-матчингом (`клиент`, `нож`, `сталь`, `камень`):

| Результат поиска | Поведение |
|---|---|
| Топ-1 score ≥ 80 **и** отрыв от топ-2 ≥ 30 | Молча подставить + тост «Сталь: AUS-8» |
| Несколько кандидатов / низкий score | Список с номерами под полем; ждать выбор |
| 0 совпадений (score топ-1 < 20) | Placeholder поля → «ввести вручную» |

**Числовые поля** (`угол`, `цена`) — всегда молча подставляются, без подтверждения. Ошибка → `сотри <поле>` + повторить.

## Выбор из списка кандидатов

Когда список висит, выбор по любой из трёх форм:
- Порядковое: `первый`, `второй`, `третий`...
- Число: `один`, `два`, `три`...
- Само значение из списка: `восемь` → подберёт AUS-8 (текущий двухфазный паттерн)

## Поведение списка при сторонних командах (Вариант β)

| Что сказали при висящем списке | Что делаем |
|---|---|
| Корректный выбор | Подставляем, список исчезает |
| Любая другая валидная команда поля / навигации | Команда выполняется, список исчезает, поле остаётся пустым |
| Команда того же поля заново (`сталь d2`) | Перезапуск поиска с новым значением |
| Мусор / нераспознанное | Список висит, ничего не делаем |
| `стоп` | Диктовка выключается, список исчезает |

Никакого «окна на отмену» не делаем. Откат всегда через `сотри <поле>` — работает в любой момент.

## Реакция на submit с accepted vs done

- `сохранить` → submit с `status: 'accepted'`, форма закрывается, диктовка выключается. Возврат на C-2 или H-1.
- `готово` → submit с `status: 'done'`, `doneAt = now()`, форма закрывается, диктовка выключается, далее **ручной** поток «фото после» (нативный пикер не управляется голосом — за рамками пилота).
- Редактирование accepted → done: тот же `SharpeningForm.tsx` в edit-mode, диктовка работает там же. Команда `готово` работает независимо от текущего статуса.

## Без TTS

Озвучка ответов (`SpeechSynthesis`) в первой итерации не делается. Обратная связь только визуальная:
- Тосты подтверждений («Сталь: AUS-8»)
- Список кандидатов на экране
- Индикатор «слушаю» (пульсация в шапке)
- Последняя распознанная фраза мелким шрифтом

TTS — кандидат на итерацию 3, если боевой опыт покажет, что нужен eyes-free.

## Технические компоненты

### `parseCommand` — чистая функция

```
src/utils/voiceCommand.ts
src/utils/voiceCommand.test.ts
```

```typescript
type Command =
  | { kind: 'field'; field: FieldKey; value: string }
  | { kind: 'addStone' }
  | { kind: 'clear'; field: FieldKey }
  | { kind: 'removeLastStone' }
  | { kind: 'nav'; action: 'next' | 'prev' | 'cancel' }
  | { kind: 'submit'; markDone: boolean }
  | { kind: 'stop' }
  | { kind: 'confirmCancel' }                  // "да" в окне подтверждения отмены
  | { kind: 'pickFromList'; hint: string }     // "первый" / "один" / "восемь"
  | { kind: 'repeat' }
  | { kind: 'unknown' }

function parseCommand(
  text: string,
  ctx: { step: 1 | 2; awaitingListField: FieldKey | null; awaitingCancelConfirm: boolean }
): Command
```

Тестируется юнитами без браузера (как `voiceMatch.test.ts`).

### `useDictationMode` — хук

```
src/hooks/useDictationMode.ts
```

```typescript
{
  isAvailable: boolean,
  isActive: boolean,
  lastTranscript: string,
  start: (onCommand: (cmd: Command, raw: string) => void) => void,
  stop: () => void,
}
```

Внутри:
- В `onresult` — `parseCommand(text, ctxRef.current)` → `onCommand(cmd, text)`
- В `onend` — если `isActive` ещё true → `recognition.start()` снова
- Счётчик подряд-ошибок (no-speech, network, aborted): на 3-й подряд → автостоп + тост «микрофон отключён»
- Контекст (`step`, `awaitingListField`, `awaitingCancelConfirm`) — через ref-объект, обновляемый родителем

### Кнопка диктовки

В шапке формы (рядом со степпером). Состояния:
- **Неактивна** — иконка mic+streamlines, тап → запустить
- **Активна** — пульсация, акцентный цвет, тап → остановить
- **Недоступна** (offline / нет SR) — disabled, прозрачная

### Диспатчер в `SharpeningForm.tsx`

Маршрутизирует `Command` в существующие функции (`setSteel`, `addStone`, `handleNext`, `handleSubmit`...). Никакой бизнес-логики в хуке.

## Feature flag

Под существующим флагом `voiceInput`. Тумблер «диктовка» в настройках не нужен — это сама кнопка на форме.

## Открытые вопросы (всплыли при реализации)

### Решено в ходе реализации

- **Префикс «состояние» → «требуется»** (2026-05-18). В исходной грамматике плана команда называлась `состояние тупой/средний/острый`, но в реальной форме поле называется «Требуется», а его чипы — `заточка / правка РК / ремонт` (типы работы, не острота клинка; поля для остроты вообще нет). Грамматика выровнена под UI: prefix → `требуется`, значения → `заточка / правка / правка рк / ремонт`. Значение `правка` и `правка рк` оба нормализуются в чип `правка РК`. FieldKey остался `'condition'` (это внутреннее имя, совпадает со стейтом `condition: string[]` в форме).
