# Баг-репорты → Telegram: настройка серверной части

Клиент шлёт баг-репорт `POST`-ом (Content-Type `text/plain`, тело — JSON с `event: 'bug_report'`)
на тот же Apps Script endpoint, что и телеметрия (`VITE_ANALYTICS_URL`). Скрипт пишет строку
в лист **BugReports** таблицы «AppTochite Data» и пересылает сообщение в Telegram-группу через бота.

**Важно про порядок раскатки:** Apps Script нужно обновить и передеплоить **до** релиза
приложения. Пока в скрипте нет `doPost`, POST-запросы будут молча теряться (клиент шлёт
в режиме `no-cors` и не видит ответ сервера).

**Режим «только таблица» (без бота):** Telegram — опциональная надстройка. Если Script
Properties `TG_BOT_TOKEN` / `TG_CHAT_ID` не заданы, `sendToTelegram` молча выходит, и
репорты просто копятся на листе BugReports. Достаточно выполнить шаги 3–5, пропустив 1–2;
бота можно подключить в любой момент позже — только добавить два свойства, передеплой
не нужен. Чтобы не проверять таблицу вручную, можно включить встроенные уведомления:
в таблице **Инструменты → Настроить уведомления → при любых изменениях — письмом сразу**.

---

## Шаг 1. Создать бота

1. В Telegram открыть **@BotFather** → `/newbot`.
2. Имя — например `AppTochite Bugs`, username — например `apptochite_bugs_bot`.
3. Сохранить выданный **токен** (`1234567:AA...`) — он пойдёт в Script Properties, не в код.

## Шаг 2. Создать группу и узнать chat_id

1. Создать приватную группу (например «AppTochite баги»), добавить туда бота.
2. Написать в группу любое сообщение.
3. Открыть в браузере:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. В ответе найти `"chat":{"id":-100xxxxxxxxxx,...}` — это **chat_id** (у групп он отрицательный).
   Если ответ пустой — удалить бота из группы, добавить снова и повторить.

## Шаг 3. Обновить код в Apps Script

Актуальный исходник скрипта версионируется в репо: **`scripts/analytics-sheet.gs`**
(секция «Баг-репорты»: `doPost`, `appendBugRow`, `sendToTelegram`, `logError_`, `testPost`).

Открыть редактор скрипта телеметрии (тот, чей URL лежит в `VITE_ANALYTICS_URL`) и заменить
содержимое файла целиком на текущий `scripts/analytics-sheet.gs`. Скрипт standalone,
поэтому таблица открывается через `SpreadsheetApp.openById(SPREADSHEET_ID)` — не менять
на `getActiveSpreadsheet()`.

## Шаг 4. Секреты (только для Telegram-режима)

В редакторе Apps Script: **Project Settings → Script Properties** → добавить:
- `TG_BOT_TOKEN` = токен из шага 1
- `TG_CHAT_ID` = chat_id из шага 2

В режиме «только таблица» этот шаг пропускается.

## Шаг 5. Проверка в редакторе + деплой

1. В редакторе выбрать функцию **`testPost`** в выпадающем списке над кодом → **Run**.
   При первом запуске Google попросит авторизацию — разрешить доступ (это одноразово;
   без авторизации не будет работать и опубликованный `doPost`).
   Проверить: в таблице «AppTochite Data» появился лист **BugReports** со строкой
   «тестовый репорт из редактора».
2. **Deploy → Manage deployments → ✏️ → Version: New version → Deploy.**
   Это обязательный шаг: без новой версии код `doPost` не попадёт в опубликованный URL.
   URL при этом не меняется — в приложении ничего править не нужно.
   Доступ у деплоя должен остаться **«Anyone»** (как у телеметрии).

## Шаг 6. Сквозная проверка (снаружи, как шлёт приложение)

`VITE_ANALYTICS_URL` хранится в GitHub Secrets, но тот же URL вшит в опубликованный
JS-бандл на GitHub Pages — он публичный по определению. Тест из консоли браузера
(F12 → Console на любой https-странице):

```js
fetch('<URL скрипта>', {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain;charset=utf-8' },
  body: JSON.stringify({ event: 'bug_report', ts: new Date().toISOString(),
    deviceId: 'test', platform: 'web', displayMode: 'browser', appVersion: 'test',
    contact: '@test', text: 'сквозной тест', ua: navigator.userAgent, lang: 'ru',
    online: true, clientsCount: 0, sharpeningsCount: 0 }),
})
```

Важно понимать: в консоли успех «не виден» — приложение шлёт в `no-cors`, поэтому и здесь
ответ будет непрозрачным (opaque), а promise зарезолвится даже при ошибке скрипта.
Единственный критерий успеха — **новая строка на листе BugReports**. Если строки нет:
- проверить лист **Errors** (туда пишутся ошибки парсинга payload'а);
- если нет и его — почти наверняка забыт пункт «New version» при деплое (код в
  опубликованном URL остался старым, без `doPost`).

Если задан Telegram-режим — в группе дополнительно должно появиться сообщение.
