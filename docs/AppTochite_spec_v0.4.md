# AppTochite — Функциональная спецификация v0.6

**Версия:** 0.6 · Май 2026  
**Приложение:** v1.54.0  
**Платформа:** PWA · Android (90%) · интерфейс на русском языке

---

## 1. Обзор продукта

AppTochite — мобильное приложение для профессиональных заточников ножей. Решает задачу ведения журнала заточек: фиксация клиентов, ножей, камней, параметров заточки и рекомендаций.

**Целевая аудитория:** два сегмента с единым интерфейсом:

- **Заточник как малый бизнес** — клиенты, учёт заработка, статусы
- **Заточник «для себя»** — личный журнал, коллекция

**Ключевое решение:** оба сегмента используют единый интерфейс. Пользователь «для себя» представлен как **нулевой клиент («Я»)** — создаётся автоматически при первом запуске, не удаляется.

## 2. Навигация

Нижняя панель навигации (bottom navigation bar) — постоянная, доступна со всех экранов.

**Вкладки:**

- **Клиенты** — стартовый экран
- **История** — единая лента всех заточек
- **Справочники** — три под-вкладки: Камни / Стали / Ножи

**Плавающая кнопка действия (FAB):**

- Кнопка «+ Заточка» — Material Design FAB, закреплена поверх контента в правом нижнем углу
- Доступна с любого экрана
- При нажатии из карточки клиента (C-2): предзаполняет поле клиента в форме Z-1 и скрывает его

## 3. Реестр экранов

### 3.1 Клиенты

#### C-1 — Список клиентов

- Поиск по имени или телефону
- Нулевой клиент «Я» закреплён отдельной секцией сверху — не удаляется, имеет золотую корону на аватаре
- Строка клиента: аватар с инициалами, имя, телефон, счётчик заточек с разбивкой по статусам (принят / готов)
- Кнопка «Добавить клиента» — пунктирная строка внизу списка
- Подзаголовок аппбара: общее число клиентов и заточек

> Удаление клиента — только через карточку C-2, без свайпа.

#### C-2 — Карточка клиента

- Шапка: аватар (фото или инициалы), имя, телефон, Телеграм
  - Тап по телефону → копирует в буфер, показывает toast «Телефон скопирован»
  - Тап по Телеграму → открывает `t.me/username` в браузере (редирект в приложение)
- Метрики: заточек всего
- Кнопки: «Редактировать», «+ Новая заточка», «Повторить заточку» (создаёт новую с предзаполненными данными последней)
- История заточек клиента: нож, сталь + угол, цена, статус-пилюля; пагинация по 10 записей
- Фильтр по ножу — появляется при двух и более разных ножах у клиента

#### C-3 — Добавить / редактировать клиента

- «Готово» в аппбаре — неактивен пока имя пустое
- Кнопка «Добавить / Сохранить» дублирует действие внизу формы
- «Отмена» — возврат без сохранения

| Поле | Описание | Обяз. |
|---|---|:---:|
| Имя | текстовое поле | ✱ |
| Телефон | маска `+7 (___) ___-__-__` | |
| Телеграм | префикс `@`, username без собаки | |
| Аватар | фото из камеры или галереи; хранится как base64 в `Client.avatar` | |

- Режим редактирования: внизу ссылка «Удалить клиента» (красная, без рамки) → открывает M-1

> Удаление клиента удаляет все его заточки.

### 3.2 История

#### H-1 — Лента заточек

- Аппбар: «История» + подзаголовок «N заточек · X ₽»
- Поиск по клиенту, марке ножа, стали, камням, комментарию (сниппет совпадения в результате)
- Фильтр чипами по статусу: **Все / Принят / Готов** *(статус «В работе» удалён)*
- Лента сгруппирована по месяцам
- Строка: нож + дата + thumbnail фото, клиент, сталь + угол, цена, статус-пилюля
- Тап на строку → Z-2

### 3.3 Бэкап и данные

#### BK-1 — Экран бэкапа

Доступен из нижней навигации или иконки в шапке C-1.

**Экспорт — JSON бэкап**

- Кнопка «Экспортировать данные» → стандартный Android share sheet
- Формат файла: `apptochite_backup_ГГГГ-ММ-ДД.json`
- Содержимое: клиенты, заточки, пользовательские справочники, фото в base64

> Файл может занять несколько десятков МБ из-за фото в base64.

**Экспорт — CSV**

- Кнопка «Экспортировать в CSV» → скачивание файла
- Формат: `apptochite-sharpenings-ГГГГ-ММ-ДД.csv`
- Содержимое: заточки с полями: № заточки, клиент, нож, сталь, угол, цена, статус, даты
- Разделитель `;`, UTF-8 BOM — совместим с Excel и Google Sheets

**Автобэкап**

- Работает автоматически без участия пользователя — диалогов и разрешений не требует
- Использует OPFS (Origin Private File System): файл `apptochite-auto.json` в приватном хранилище браузера
- Запускается при каждом открытии приложения (холодный старт и возврат из фона через `visibilitychange`)
- Файл недоступен из файлового менеджера — только через экран BK-1 («Восстановить из авто-бэкапа»)
- BK-1 показывает дату и размер последнего авто-бэкапа
- Прогресс-бар заполнения хранилища отображается в BK-1

**Импорт данных**

- Кнопка «Импортировать данные» → нативный файловый picker
- **Две стратегии восстановления:**
  - **«Объединить»** — merge: новые записи добавляются, конфликты решаются last-write-wins по `updatedAt`; экран итогов (добавлено / обновлено / без изменений)
  - **«Заменить всё»** — полная замена текущих данных; предупреждение красным
- Toast по завершении: «Данные восстановлены · N заточек, N клиентов»

#### Планируемые улучшения надёжности

Не реализовано. Закрывают классы рисков потери данных, которые **облачный бэкап не закрывает** (или закрывает не полностью). Рекомендованный порядок — по убыванию ROI:

**1. Soft delete + корзина**
- Поле `deletedAt?: Date` на `clients`, `sharpenings`, `stones`, `steels`, `knives`
- Удаление через M-1 = пометка `deletedAt`, не физическое удаление
- Все списки и выборки фильтруют записи с `deletedAt`
- Корзина в настройках: восстановление и принудительное удаление
- Физическое удаление через 30 дней после soft-delete
- **Закрывает:** случайное удаление пользователем — самый частый реальный кейс потери данных. Облако НЕ помогает: удаление синканётся в облако
- **Бонус:** обязательная инфраструктура для мультидевайс-облака (tombstones)

**2. Автоснапшот перед миграцией схемы**
- При запуске, если `db.version` в IndexedDB ниже текущей кодовой версии — до запуска миграции экспортировать состояние в `pre-migration-backup-v{old}-{ts}.json`
- Хранить 30 дней
- **Закрывает:** ошибки в нашем релизе с миграцией. OPFS-автобэкап последний может быть уже после поломки

**3. История бэкапов**
- Хранить N последних снапшотов (например, 7) вместо перезаписи одного файла
- Применимо и к OPFS-автобэкапу, и к будущему облачному
- **Закрывает:** битый/неполный бэкап перезатёр предыдущий хороший

**4. Расшаривание бэкапа через Web Share API**
- Кнопка «Поделиться бэкапом» в BK-1 → системный share sheet
- Пользователь выбирает: Telegram Saved Messages, Gmail, любое cloud-приложение
- **Закрывает:** off-site копия без OAuth-интеграций. Не заменяет облако для мультидевайс-синка, но для значительной части пользователей закрывает запрос «храню копию вне устройства» при минимальных затратах. Стоит рассмотреть **до** полноценной облачной синхронизации

**5. Проверка целостности бэкапа после записи**
- После `exportBackup` + write — прочитать обратно, `JSON.parse`, сверить число клиентов и заточек
- Если расхождение — повторить попытку, не отмечать как успешный
- **Закрывает:** ложное чувство безопасности при битом бэкапе

**6. Эскалация напоминания о бэкапе**
- Текущий `BackupReminder` напоминает раз в 7 дней с одинаковым весом
- Дополнительно учитывать: количество новых записей с последнего бэкапа («у вас 47 новых заточек»), общую давность (30+ дней — красный баннер)
- **Закрывает:** активный пользователь смахивает напоминание неделями, накапливая много неспасённой работы

**7. PWA install prompt с фокусом на сохранность**
- При первом запуске не-установленной версии после N заточек — баннер «Установите приложение, чтобы данные не пропали при чистке браузера»
- Установленная PWA защищена от очистки browser data лучше, чем вкладка
- **Закрывает:** R-3 из таблицы рисков (пилоты использовали как вкладку)

**Связь с облачным бэкапом:**
- Пункты 1 (soft delete) и 3 (история) — **обязательная инфраструктура** для мультидевайс-облака. Реализация заранее снижает риск облачного релиза
- Пункт 4 (Web Share) — частичная альтернатива облаку. Стоит честно взвесить, не закрывает ли он запрос пользователей раньше, чем понадобится полное OAuth-облако
- Пункты 2, 5, 6, 7 — ортогональны облаку, ценны сами по себе

### 3.4 Создание и просмотр заточки

#### Z-1 — Форма заточки (stepper: Приёмка → Заточка)

**Шаг 1 — Приёмка:**

| Поле | Описание | Обяз. |
|---|---|:---:|
| Клиент | выбор из списка. Скрыто если пришли из C-2 | ✱ |
| Марка ножа | автодополнение из справочника + история клиента; подсказки сортируются по частоте | ✱ |
| Сталь | автодополнение из справочника | |
| HRC | выбор из диапазона 50–70, одно значение или пусто | |
| Тип работы | мультивыбор чипами: **заточка / правка РК / ремонт** | |
| Дата приёма | по умолчанию сегодня | ✱ |

> После сохранения шага 1 предлагается фото «До» (можно пропустить).

**Шаг 2 — Заточка:**

| Поле | Описание |
|---|---|
| Угол заточки | числовое поле, градусы на сторону |
| Камни | автодополнение из справочника; теги с порядковым номером; последний — финишный (плашка FIN) |
| Создать камень | диалог с блюром фона прямо в шаге 2: бренд, зернистость (необяз.), тип, СОЖ |
| Комментарий и рекомендации | textarea, 2–3 строки, растягивается |
| Цена | числовое поле, ₽ |
| Статус | **принят / готов**, по умолчанию «принят» |

> Статус «в работе» удалён из системы. Существует только два состояния: принят → готов.

**Голосовой ввод полей** (opt-in, включается в «О программе»):

- Кнопка микрофона у каждого поля: двухфазный ввод — произносим значение → список совпадений → выбираем
- Fuzzy match с транслитерацией и bigram-сходством (voiceMatch.ts)
- В офлайне кнопка `disabled`, тап → toast «Голосовой ввод недоступен офлайн»

#### Z-2 — Детальная запись (просмотр)

- «Изменить» — только в аппбаре справа
- Шапка: клиент (аватар + имя) ниже названия ножа, чипы (тип работы, сталь, HRC)
- Статус-пилюля + цена + даты (принят / готов)
- Заточка: угол, камни тегами с порядком; последний — FIN
- Комментарий
- Фото: два слота «до» и «после»
  - Баннеры «Добавить фото» — появляются после шага 1 (до) и при статусе «готов» (после)
  - Тап на фото → полноэкранный просмотр (PhotoLightbox) со свайпом
  - Удаление фото — крестик на миниатюре
  - Первое фото отмечается как «обложка» (badge)
  - Шаринг отдельного фото с вотермарком @AppTochite через `PhotoShareSheet`
- **Кнопка «Создать фото-отчёт»** — появляется если есть фото «после»; canvas-карточка с ножом, сталью, углом и камнями; шаринг через Web Share API
- «Повторить заточку» — создаёт новую заточку с данными текущей (нож, сталь, камни)
- «Удалить заточку» — тихая красная ссылка внизу страницы → M-1

> Дата готовности проставляется автоматически при статусе «готов».

### 3.5 Справочники

#### S-1 / S-2 / S-3 — Камни / Стали / Ножи

- Переключение сегментированным контролом (3 вкладки)
- Поиск в каждой вкладке; для камней — поиск по типу через `*` (например, `*алмаз`), по СОЖ через `*вода`/`*масло`
- Мульти-токенный поиск: `GRIN 120` находит `Grinderman OA CLR 120`
- Кнопки «Добавить камень / сталь / нож» — вверху каждой вкладки
- Мультиселект: долгий тап → режим выделения
  - Кнопка «Выбрать все» для быстрого выделения всего списка
  - Групповое удаление выбранных позиций
- Редактирование позиции — выбрать и нажать «Изменить»; стандартные камни редактируются с бейджем «Мой»

**Камни — тип абразива (9 значений):**

| Значение | Описание |
|---|---|
| `galvanic` | Гальванический |
| `ao` | Оксид алюминия (белый, розовый, корундовый) |
| `kk` | Карбид кремния (чёрный корундовый) |
| `diamond` | Алмазный |
| `elbor` | Эльборный (кубический нитрид бора) |
| `natural` | Натуральный |
| `pritir` | Притир |
| `ceramic` | Керамика |
| `other` | Иное |

**Поля камня:** бренд, зернистость *(необязательна, с выбором единицы: FEPA / JIS / мкм)*, тип абразива, СОЖ (вода/масло/оба), описание

**Конвертер гритностей** — барабаны-спиннеры FEPA / JIS / мкм в справочнике камней; переключение конвертирует значение автоматически. Включает таблицу соответствий (33 строки, включая FEPA 90/180, JIS 320/1200/6000, ГОСТ).

**Тепловая карта** — иконка в шапке справочника камней; открывает отдельный экран с частотой использования каждого камня. Финишный камень учитывается отдельной позицией.

**Финишный камень** — последний камень в списке заточки; отмечается плашкой **FIN** на теге.

**Ближайшие гритности** — в списке камней показываются ближайшие значения выше и ниже текущего камня.

**Поля стали:** название, HRC, описание *(рекомендуемый угол удалён)*

**Поля ножа:** бренд, страна, сталь (с автодополнением), рекомендуемый угол, тип, описание

## 4. Модальные оверлеи

#### M-1 — Подтверждение удаления

- Появляется при удалении клиента (из C-3) или заточки (из Z-2)
- Текст предупреждения о последствиях
- Кнопки: «Отмена» и «Удалить» (красная)

#### M-2 — Фото кромки

- Открывает камеру устройства или галерею (через `PhotoSourceSheet`)
- Превью снятого фото
- Кнопки: «Переснять» и «Сохранить»

## 5. Сквозные UX-решения

### Онбординг

- `OnboardingSheet` — welcome-экран при первом запуске (определяется по отсутствию `firstLaunchAt` в `settings`)
- Ссылка на инструкцию в «О программе»

### Toast-уведомления

- «Телефон скопирован» — при тапе на телефон в C-2
- Всплывает снизу, исчезает через 2–3 секунды, не требует действия

### Предупреждение о браузере

- `BrowserWarning` — отображается при открытии в Telegram, Instagram и других встроенных браузерах

### Статусы заточки

| Статус | Цвет | По умолчанию |
|---|---|---|
| принят | синий (`#4A90D9`) | при создании |
| готов | зелёный (`#3DB87A`) | вручную → автоматически ставит дату готовности |

> Статус «в работе» (янтарный) удалён — не создавать, не отображать.

### Фото до / после

- Фото «До» — предлагается после сохранения шага 1 (Приёмка), можно пропустить
- Фото «После» — предлагается при смене статуса на «готов», можно пропустить
- До 5 фото на заточку, сжимаются перед сохранением
- Хранятся как `base64[]` в полях `photosBefore` / `photosAfter`
- Шаринг фото с вотермарком @AppTochite — `PhotoShareSheet`

### Автодополнение

- Поля «Марка ножа», «Сталь» и «Камень» — подсказки из справочника
- Мульти-токенный поиск (несколько слов находят одну запись)
- Двойной тап — быстрый выбор из выпадающего списка без ввода
- Создание нового значения — сохранится в справочнике

### Аналитика

- Opt-out: включена по умолчанию, отключается в «О программе»
- Офлайн-буфер: события сохраняются в `analyticsQueue` и отправляются при восстановлении сети

### Иконки

- Все иконки — встроенные SVG-компоненты (без внешних зависимостей)
- Эмблема AppTochite (AppLogo) — на основных экранах

## 7. База данных

**Движок:** Dexie.js (IndexedDB), локально на устройстве, текущая версия схемы **v6**.

**Таблицы:**

| Таблица | Описание |
|---|---|
| `clients` | Клиенты, включая нулевого «Я» (`isSelf: true`) |
| `sharpenings` | Заточки. Поле `stones` — embedded JSON, не отдельная таблица |
| `stones` | Справочник камней |
| `steels` | Справочник сталей |
| `knives` | Справочник ножей |
| `meta` | Служебная таблица ключ-значение (хранит `seedVersion`) |
| `settings` | Device-specific состояние (`firstLaunchAt`, `lastBackupAt`, автобэкап). **Не входит в бэкап** |
| `analyticsQueue` | Офлайн-буфер событий аналитики. **Не входит в бэкап** |

**Важные ограничения:**
- `Sharpening.status` — только `'accepted' | 'done'` (тип `SharpeningStatus`)
- `Sharpening.doneAt` — обязателен только при `status === 'done'`
- `Sharpening.stones` — `SharpeningStone[]` (embedded JSON): `{ name: string, order: number }`; поиск/фильтрация требует fullscan
- `Stone.type` — 9 значений, включая `'other'`
- `Stone.coolant` — необязательное: `'water' | 'oil' | 'both'`
- `Stone.grit` — необязательное поле; сопровождается `gritUnit: 'fepa' | 'jis' | 'mk'` и `gritMk: string` для мкм
- `Client.avatar` — необязательное поле, base64-строка

## 10. Бэклог (за рамками текущей версии)

**Средний приоритет:**
- Суммарная выручка в карточке клиента (C-2) — подсчёт по заточкам со статусом `done`
- Статистика по камням (fullscan `sharpenings` — учесть при проектировании)
- Финансовая аналитика — выручка за период, средний чек

**Низкий приоритет:**
- S-4 — карточка позиции справочника с кнопкой «Использовать в заточке»
- Drag-to-reorder камней в форме заточки (текущий workaround — удалить и добавить заново)
- Расширение голосового ввода на другие экраны
- Голосовая навигация между полями/шагами
- Уведомление клиенту «нож готов»
- Распознавание ножа по фото — Claude API

**Нет приоритета:**
- Облачная синхронизация
- Собственный домен
- Мультипользовательский режим
- Мультиязычность
- Общие облачные справочники
