## 1. Как запускать тесты

### Автоматические (запускает Claude)

```bash
npm test           # одиночный прогон, результат в терминале
npm run test:watch # следит за изменениями файлов
```

**Файлы тестов:**
- [src/utils/backup.test.ts](../src/utils/backup.test.ts) — логика бэкапа/восстановления
- [src/db/db.test.ts](../src/db/db.test.ts) — операции с базой данных
- [src/db/seed.test.ts](../src/db/seed.test.ts) — seed-миграции
- [src/utils/voiceMatch.test.ts](../src/utils/voiceMatch.test.ts) — fuzzy-матчинг голосового ввода

**Итого: 219 тестов, все зелёные.**

### Ручные

Выполнять в Chrome DevTools (Mobile → Pixel 5) или на Android-устройстве.

**Подготовка:** Открыть DevTools → Application → IndexedDB → Delete database → обновить страницу (seed накатится автоматически).

## 2. 🤖 Автоматические тесты

Эти тесты Claude запускает сам. Описание для понимания покрытия.

### Backup-утилиты (`backup.test.ts`)

| Группа | Что проверяется |
|--------|-----------------|
| `isValidBackup` | Принимает корректный бэкап; отклоняет null, строку, пустой объект, неверную version, отсутствующий data, нарушение структуры; совместим с бэкапами без поля `meta` |
| `reviveDates` | ISO-строки конвертируются в Date; обычные строки, числа, null не трогаются; работает через `JSON.parse` |
| `buildCSV` | UTF-8 BOM в начале; разделитель `;`; CRLF между строками; экранирование `"` внутри значений; null/undefined → пустая строка |
| `buildSharpeningCSV` | Первая строка — заголовки с нужными колонками; заточка без камней — 1 строка данных; заточка с N камнями — N строк; статус `done`→«Готово», `accepted`→«Принят» |
| `exportBackup + restoreBackup` | Экспорт пустой БД даёт правильную структуру; полный цикл: данные в БД → экспорт → очистка → восстановление → данные совпадают; `isSelf` сохраняется; фото в base64 восстанавливаются; при ошибке транзакция откатывается |
| `mergeBackup` | Новые записи из файла добавляются; запись только на устройстве — остаётся; конфликт: `updatedAt` файла новее — обновляется; конфликт: `updatedAt` устройства новее — остаётся; бэкап без `updatedAt` — трактуется как epoch |

### База данных (`db.test.ts`)

| Группа | Что проверяется |
|--------|-----------------|
| `Клиенты` | CRUD (создание с id, isSelf, avatar, редактирование, удаление); каскадное удаление заточек; телефон и telegram как необязательные поля |
| `Заточки` | CRUD; статус `accepted` без `doneAt`; статус `done` с `doneAt`; stones как embedded JSON; фото в base64; удаление одного фото; изменение статуса; фильтрация по `clientId` и `status` |
| `Камни` | CRUD; создание без гритности; все 9 типов (включая `ceramic` и `other`); поля `gritUnit`, `gritMk`; поле `coolant`; фильтрация кастомных |
| `Стали` | CRUD; HRC |
| `Ножи` | CRUD; полные данные; массовое удаление |
| `Meta` | Запись и обновление `seedVersion` |

### Seed-миграции (`seed.test.ts`)

| Группа | Что проверяется |
|--------|-----------------|
| Первый запуск | Seed накатывается при пустой БД |
| Повторный seed | При наличии `seedVersion` seed не дублирует данные |
| Обновление seed | Новая версия добавляет только новые записи |

> Раньше тут было 2 known-failing — их обновили под новый идемпотентный seed-catalog-sync (см. коммит `fix: ...`).

### Голосовой матчинг (`voiceMatch.test.ts`)

| Группа | Что проверяется |
|--------|-----------------|
| Транслитерация | Русский текст → латиница для сравнения |
| Bigram-сходство | Нечёткое совпадение строк |
| Fuzzy match | Матчинг ножей, сталей, камней по голосовому вводу |

### Парсер команд диктовки (`voiceCommand.test.ts`) — итерация 2

> Статус: ✅ Реализовано — 67 тестов в 11 группах

Парсер `parseCommand(text, ctx)` — чистая функция, тестируется без браузера.

| Группа | Что проверяется |
|--------|-----------------|
| Команды Приёмки | `клиент иван` → `{kind: 'field', field: 'client', value: 'иван'}`; `нож шеф`; `сталь d2`; `требуется заточка`/`правка`/`правка рк`/`ремонт` → chip; `примечание ...` → весь хвост попадает в value |
| Команды Заточки | `угол 20` → number=20; `цена 500`; `камень бельгийский`; `добавить` → `{kind: 'addStone'}`; `удали последний камень` → `removeLastStone` |
| Strict по шагу | `угол 20` при `ctx.step === 1` → `unknown` (не авто-переходим); `клиент иван` при `step === 2` → `unknown` |
| Навигация | `дальше` / `следующее` → `nav:next`; `назад` → `nav:prev`; `сохранить` → `submit{markDone:false}`; `готово` → `submit{markDone:true}`; `стоп` / `пауза` → `stop`; `отмена` → `nav:cancel` |
| Подтверждение отмены | При `ctx.awaitingCancelConfirm === true`: `да` → `confirmCancel`; любая другая фраза → обычный парс |
| Выбор из списка | При `ctx.awaitingListField === 'steel'`: `первый` / `один` / `8` → `pickFromList`; `сталь d2` → `field` (перезапуск поиска того же поля); `угол 20` → `field` (отменяет список); мусор → `unknown` (список висит) |
| Коррекции | `сотри сталь` → `clear:steel`; `очисти примечание` → `clear:notes`; `повтори` / `что услышал` → `repeat` |
| Числа словами | `один`, `два`, `три`, ..., `двадцать`, `двадцать пять` → корректное число для угла/цены |
| Шум распознавания | `сталь австрия восемь` (вместо «аус-8») всё равно даёт `field:steel` с value «австрия восемь» — fuzzy решит дальше; нерелевантные слова до префикса игнорятся |
| Регистр и пунктуация | Команда нечувствительна к регистру, лишним пробелам и финальной точке |
| Пустой / мусорный ввод | Пустая строка, фраза без префикса (`иван`) → `unknown` |

Минимум 30 кейсов суммарно, в духе `voiceMatch.test.ts`.

## 4. 👤 Ручные тесты — бэкап и восстановление

Это **самый важный ручной раздел**. Прогонять при каждом значимом обновлении.

### 4.1 Подготовка тестовых данных

Перед тестированием создать:
- 2 клиентов (не «Я»)
- 2–3 заточки с разными статусами
- Минимум 1 заточку с фото «До» и «После»
- 1 кастомный камень в справочнике

### 4.2 Экспорт JSON

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| B-1 🔴 | Бэкап → «Экспортировать данные» | Файл `apptochite_backup-YYYY-MM-DD.json` скачан |
| B-2 🔴 | Открыть файл в текстовом редакторе | Структура: `{ version: 1, exportedAt, data: { clients, sharpenings, stones, steels, knives, meta } }` |
| B-3 🔴 | Найти в JSON заточку с фото | Поля `photosBefore`/`photosAfter` — массивы base64-строк |
| B-4 🔴 | Найти кастомный камень | Присутствует с `isCustom: true` |

### 4.3 Экспорт CSV

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| B-5 🟡 | Бэкап → «Экспортировать в CSV» | Файл `apptochite-sharpenings-YYYY-MM-DD.csv` скачан |
| B-6 🟡 | Открыть в Excel или Google Таблицах | Кириллица читается, все колонки присутствуют, разделитель `;` |

### 4.4 Восстановление — сценарий A: чистая БД

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| R-1 🔴 | Удалить всю БД (DevTools) → обновить | Только «Я» в списке клиентов |
| R-2 🔴 | Бэкап → выбрать `.json` файл | Показывается превью: кол-во клиентов, заточек, камней |
| R-3 🔴 | «Заменить всё» → подтвердить | Toast «Данные восстановлены», редирект на список клиентов |
| R-4 🔴 | Список клиентов | Все клиенты из бэкапа присутствуют, «Я» первый |
| R-5 🔴 | Открыть заточку с фото | Фото «До» и «После» отображаются |
| R-6 🔴 | Справочник → Камни | Кастомный камень из бэкапа присутствует |
| R-7 🔴 | Статусы заточек | Совпадают с бэкапом (accepted/done) |
| R-8 🔴 | Даты | `receivedAt` и `doneAt` корректные (не «Invalid Date») |

### 4.5 Восстановление — сценарий B: «Заменить всё» поверх существующих данных

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| R-9 🔴 | Создать нового клиента (не из бэкапа) | Клиент в списке |
| R-10 🔴 | Загрузить старый бэкап → «Заменить всё» | Предупреждение красным: «Удалит все текущие данные» |
| R-11 🔴 | Подтвердить | Новый клиент исчез, данные из бэкапа восстановлены |

### 4.5б Восстановление — сценарий C: «Объединить» (merge)

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| M-1 🔴 | Создать клиента X на устройстве (нет в бэкапе) | Клиент X в списке |
| M-2 🔴 | Загрузить бэкап с клиентом Y (нет на устройстве) | Превью показывает кол-во записей в файле |
| M-3 🔴 | Нажать «Объединить» | Экран итогов: добавлено ≥1, без изменений ≥1 |
| M-4 🔴 | Проверить список клиентов | Присутствуют и X, и Y — никто не потерян |
| M-5 🟡 | Изменить заточку на устройстве, загрузить старый бэкап с той же заточкой → «Объединить» | Версия с устройства осталась (она новее) |
| M-6 🟡 | Загрузить бэкап с записью, `updatedAt` которой новее → «Объединить» | Версия из файла победила, `обновлено: 1` |

### 4.6 Некорректный файл

| # | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| R-12 🔴 | Выбрать произвольный `.json` без нужной структуры | Toast с ошибкой, текущие данные не тронуты |
