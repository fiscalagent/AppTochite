# Cloud proxy (Cloudflare Worker)

CORS-прокси для **скачивания** бэкапа с Яндекс.Диска. Нужен, потому что файловые
серверы Яндекса не отдают CORS-заголовки, и браузер не может прочитать тело файла
(`TypeError: Failed to fetch`). Заливка (upload) и получение ссылки работают без прокси.

## Что он делает

1. Приложение само получает у Яндекса короткоживущую **подписанную ссылку** на файл
   (шаг к `cloud-api.yandex.net`, CORS там есть; токен наружу не уходит).
2. Приложение зовёт Worker: `GET <worker>/?url=<подписанная ссылка>`.
3. Worker качает файл серверно (CORS на сервер не действует) и отдаёт байты приложению
   с заголовком `Access-Control-Allow-Origin`.

Worker видит только содержимое одного файла транзитом, **без OAuth-токена** и без
доступа к Диску. Состояния нет — деплой один раз, обслуживать нечего.

## Деплой

1. Cloudflare → **Workers & Pages** → **Create application** → **Create Worker**.
2. Назвать, например, `cloud-proxy` → **Deploy**.
3. **Edit code** → вставить содержимое [`cloud-proxy.js`](./cloud-proxy.js) → **Deploy**.
4. Скопировать URL воркера (вид `https://cloud-proxy.<account>.workers.dev`).

## Подключение к приложению

В GitHub-репозитории: **Settings → Secrets and variables → Actions → New repository secret**

- Name: `VITE_CLOUD_PROXY_URL`
- Value: URL воркера (без завершающего `/`)

Любой пуш в `main` пересоберёт приложение — кнопки «Объединить»/«Скачать файл» в облаке
заработают. Пока секрет не задан, фича «спит» и ведёт к восстановлению из файла.

## Безопасность

- `ALLOWED_ORIGIN` в [`cloud-proxy.js`](./cloud-proxy.js) — только домен приложения
  (по умолчанию `https://fiscalagent.github.io`). Чужие сайты воркером пользоваться не
  смогут. Поменяйте при смене хостинга.
- `ALLOWED_HOST` — проксируются только хосты Яндекс.Диска, чтобы это не стал открытый
  релей.

## Локальная разработка

Worker отдаёт CORS только на `ALLOWED_ORIGIN` (прод-домен), поэтому с `localhost`
вызов прокси упрётся в CORS. Тестировать облачное скачивание — на задеплоенном сайте.
